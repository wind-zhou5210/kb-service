# 工作空间体验优化与增量更新 需求规范

Version: 1.0
Created: 2026-07-31
Status: Draft

## 1. 背景

工作空间（Workspace）功能上线后，收集到三个待优化问题：

1. **分享页目录树无法隐藏**：分享页（SharedWorkspace）左侧目录树侧栏固定展示、无法收起，导致内容显示区过小，尤其在预览宽幅 HTML 页面时体验较差。
2. **分享页内容区底部留白**：分享页打开 HTML 文件时，内容区高度未充满视口，底部出现明显留白区域。
3. **缺少增量更新能力**：当前工作空间内容更新只能整包重新上传，用户误以为需要"删除工作空间后重建"才能更新内容，而删除工作空间会导致已生成的分享链接失效，造成分享链接被迫重新分发。

---

## 2. 根因分析（已验证）

### 2.1 分享页目录树无法隐藏

- 详情页 `WorkspaceDetail.tsx` **已实现**桌面端侧栏折叠（状态通过 localStorage 持久化）与移动端 Drawer 抽屉两套交互。
- 分享页 `SharedWorkspace.tsx` 侧栏宽度硬编码为 `280px`，**没有任何折叠控制**，桌面端与移动端均无法收起目录树。

### 2.2 分享页内容区底部留白

- 分享页渲染 HTML 文件时使用的 `HtmlSandbox` 组件**未传入 `fill` 属性**。
- 非 fill 模式下，`HtmlSandbox` 按 `innerHeight - 52 - 44 - 48` 计算固定高度——该公式假定页面存在共计 144px 的头部结构（顶栏 52px + 标签栏 44px + 面包屑 48px）。
- 分享页并没有这 144px 的头部结构，因此计算出的高度偏小，导致内容区底部出现约 144px 的留白。

### 2.3 缺少增量更新能力

- 后端目前仅有 `POST /api/workspaces/{ws_id}/upload` 一个内容写入端点，语义为**全量 zip 覆盖**，没有单文件的新增/替换/删除端点。
- 经验证：全量上传**并不会**清空 `share_token`，分享链接失效仅发生在**删除工作空间**这一场景。用户"更新内容必须删除重建"的认知是误解，但产品上确实缺少轻量的单文件增量更新能力与相应的提示引导。

---

## 3. 方案设计

### 3.1 分享页目录树折叠

- 分享页新增**顶部工具条**，包含：折叠按钮 + 工作空间名 + 只读分享标识。
- **桌面端**：点击折叠按钮时 `aside` 宽度在 `0 / 280px` 之间过渡动画收起与展开；折叠状态持久化到 localStorage，key 为 `kb_shared_ws_sidebar_collapsed`，刷新页面后保持。
- **移动端**：目录树改用 Drawer 抽屉呈现，与详情页移动端交互一致。

### 3.2 分享页高度修复

- 分享页 `HtmlSandbox` 改用 **fill 模式**，并在外层包裹 `height: 100%` 容器。
- 分享页 `main` 区域补充 `minHeight: 0`，保证 flex 布局下内容区正确撑满视口且可收缩。

### 3.3 单文件增量更新 API 契约

#### 3.3.1 新增/替换单文件

```
POST /api/workspaces/{ws_id}/files?path={相对路径}
鉴权: 需认证（登录用户）
请求体: multipart/form-data，file 字段为文件内容
成功: 200
  {"status": "created" | "updated" | "unchanged", "path": "...", "sha1": "...", "size": ...}
```

- 语义：`path` 指定的文件不存在则新增（`created`），存在则替换（`updated`）；若上传内容 sha1 与现有文件相同，则不做写入，返回 `unchanged`。
- 校验规则：

| 场景 | 响应 |
|------|------|
| 路径穿越（`..`、绝对路径等） | 400 |
| 隐藏文件 / `node_modules` / 禁止扩展名 | 400 |
| 文件大小超过 `workspace_max_upload_mb` | 413 |
| 工作空间不存在 | 404 |

- 本端点**不修改** `share_token`。

#### 3.3.2 删除单文件

```
DELETE /api/workspaces/{ws_id}/files?path={相对路径}
鉴权: 需认证（登录用户）
成功: 204（无响应体）
失败:
  404 文件不存在 / 工作空间不存在
```

- 语义：删除磁盘文件与对应 DB 记录，并自底向上清理删除后产生的空父目录。
- 本端点**不修改** `share_token`。

### 3.4 前端交互

- **目录树右键菜单**：启用「替换文件」「删除」操作（**仅详情页**，分享页保持只读，不出现任何写入入口）。
- **侧栏「添加文件」入口**：详情页侧栏新增「添加文件」按钮，支持指定目标相对路径后上传单文件。
- **提示引导**：上传弹窗与分享弹窗补充文案提示——「更新内容不影响已生成的分享链接」，纠正用户"更新需删除重建"的误解。

---

## 4. 分享链接生命周期策略

- `share_token` 与工作空间**一对一**绑定。
- 所有内容更新端点（全量 zip 上传、单文件新增/替换/删除）均**不修改**该字段，即内容更新永不影响已生成的分享链接。
- 分享链接仅在以下两种场景失效：
  1. 用户主动**取消分享**；
  2. 用户**删除整个工作空间**。
- 删除工作空间的确认弹窗需明确提示：「删除后分享链接将失效」。

---

## 5. 验收标准

- [ ] 分享页可折叠/展开目录树，桌面端有宽度过渡动画，刷新页面后折叠状态保持
- [ ] 分享页移动端目录树以 Drawer 呈现
- [ ] 分享页打开 HTML 文件时内容区充满视口，无底部留白
- [ ] 详情页可通过右键菜单替换/删除单文件，操作后目录树与分享页内容同步更新
- [ ] 详情页可通过「添加文件」入口新增单文件（可指定目标相对路径），目录树与分享页内容同步更新
- [ ] 全量重新上传 zip 后，原分享链接仍然有效
- [ ] 单文件端点对路径穿越请求返回 400
- [ ] 单文件端点对隐藏文件 / node_modules / 禁止扩展名返回 400
- [ ] 单文件上传超过 `workspace_max_upload_mb` 返回 413
- [ ] 上传内容 sha1 与现有文件相同时返回 `unchanged` 且不产生写入
- [ ] 删除单文件成功返回 204，文件不存在返回 404，空父目录被清理
- [ ] 分享页保持只读，无任何写入入口
- [ ] 删除工作空间确认弹窗提示「删除后分享链接将失效」
- [ ] 详情页原有功能（上传、下载、分享、删除、折叠）无回归
