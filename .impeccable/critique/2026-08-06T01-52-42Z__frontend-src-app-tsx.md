## 设计特异性结论

**LLM 评估**：视觉世界构建扎实（约 80% 扎根）——图号契约（KB/WS/SHT）、One Accent Rule、尺寸标注、注册标记、图纸网格、Mono-Spec 全部真实执行。但**交互系统层整体回潮通用模板**：ConfigProvider 只映射 8 个 token 且 fontFamily 是系统栈，所有 antd 控件（Modal/Dropdown/Select/Tag/Timeline/Tree/Button）都渲染在 OS UI 字体里；顶栏里 logo 是 IBM Plex、导航 Tab 却是系统字体。世界只活在列表页/阅读页的"表皮"，一进弹窗就掉回蓝色 antd 壳。

**确定性扫描**（detect.mjs + design-system）：**全绿**。detect.mjs 退出码 0、0 发现；设计系统检查 23 文件 0 发现（用已知违规探针验证检查活跃，非调用失效）；hook 缓存里的 35 条 index.css 发现属已修复的旧版本。

**浏览器可视化**：无浏览器自动化，未做渲染检查。

## 整体印象

从"通用后台壳 + 零设计系统"到"有明确世界观的规格单系统"的质变。阅读与列表已是产品自己的语言；剩余问题集中在**交互系统层的落地面**——弹窗、下拉、时间线、按钮字体还没被世界接管。这是"表皮 vs 全身"的最后一公里。

## 做得好的地方

1. **设计契约真实执行，不是墙纸**：靛蓝只做细结构痕的纪律贯穿全代码，暗色是重新设计（logo-mark 反白、--ink-block 更深代码块）。
2. **阅读排版真编辑级**：16px/1.7/760px 度量、h1 双线、blockquote 制图批注、阅读区留素纸，阅读列是全文最大字号。
3. **Mono 规格语言是原创签名**：`.dim` 两端刻度、注册标记、图号覆盖到顶栏/卡片/TOC/logo——最有记忆点的部分。

## 优先级问题

**P0-1 版本"查看"裸奔 pre 窗口**（VersionHistoryModal.tsx:50-53）
- 问题：window.open + document.write 裸 `<pre>`，HTML 文件显示未渲染源码，整窗无主题/字体/品牌。
- 为什么：用户追溯知识的核心动作，视觉上把产品打回"浏览器原生白纸"。
- 修复：改为应用内 Modal/路由，用 MarkdownViewer/HtmlSandbox 渲染 + .dim 版本规格条。

**P0-2 antd 控件层未进入制图世界**（main.tsx:20-38）
- 问题：只映射 8 个 token，fontFamily 系统栈；Modal/Dropdown/Select/Tag/Timeline/Tree 全系统字体。顶栏 logo(IBM Plex) 与导航 Tab(系统) 同屏。
- 为什么：特异性结论的最大漏点——世界在交互系统层回潮。
- 修复：ConfigProvider 扩展 components token，fontFamily 换 IBM Plex 栈。

**P0-3 同一种"蓝"三种 hex**（--accent #3A5BD9 / --md-color #2C5FBE / antd 预设蓝 #1677ff）
- 问题：列表用 --md-color，阅读顶栏/搜索/分享用 antd 预设蓝，同屏三蓝竞争。
- 为什么：色码语言不稳定破坏"文件类型着色"认知契约。
- 修复：antd Tag 统一喂系统 hex：`<Tag color={isMd ? 'var(--md-color)' : 'var(--html-color)'}>`。

**P1-4 工作空间侧栏 5 连图标按钮簇**（WorkspaceDetail.tsx:341-355）
- 问题：5 个并排 icon-only 按钮，删除红按钮夹中间，4px 间距无分隔。
- 修复：上传留文字标签主按钮；下载/分享/添加收进"更多"下拉；删除移出或分隔。

**P1-5 "继续阅读"承诺 > 交付**（Collections.tsx:207）
- 问题：CONTINUE READING 只跳到文档顶部，滚动位置清零；recent.ts 未存滚动比例。
- 为什么：口号"精确、受控、可追溯"，阅读位置是最基本的回溯对象。
- 修复：trackRecent 存 scrollRatio，打开后渲染再 scrollTo；或降级标题为"最近浏览"。

**P2-6 HTML 沙箱阅读无制图框架**（HtmlSandbox.tsx:83-98）
- 问题：裸 iframe 白矩形直接砸在暖纸面上，无 CSS 的 HTML 呈白块。
- 为什么：HTML 沙箱是最大差异化能力，视觉零表达。
- 修复：包一层 1px border + .dim 规格条（"HTML · 沙箱预览"），不碰 sandbox 铁律。

**P3-7 杂项**：空态组件语言分裂（EmptyState vs antd Empty vs 内联）；`.outline` 上 border-radius 无效；`.search-result-item` 规则重复定义。

## 角色红线

**Alex（自托管开发者）**：会撞上版本"查看"裸 pre 白窗——对在乎"可追溯"的用户是信誉扣分；会质疑"继续阅读"不恢复位置。

**Sam（安全敏感访客）**：HTML 沙箱边界零视觉提示（无"沙箱渲染"标签、无 iframe 边框），看不出"不可信内容被关进框里"。

## 次要观察

- 顶栏注册标记用 --ink-200 近 10% 灰，小到不可读。
- 移动端隐藏 .dim 图号，SHT 语言在手机端缺席。
- font-weight 650 用了但只加载 400/500/600 三档，浏览器会合成。
- 移动弹窗复用 .col-card 但无 .cover，层级断裂。
- 分享页 MarkdownViewer 传 onTocReady={() => {}}，丢 TOC 但静默。
- 暗色 --ink-300 作禁用文本偏弱。
- 退出登录不清理最近阅读 localStorage，单账户下是小问题。

## 可思考的问题

1. 世界是否只活在"表皮"？每次点进弹窗/下拉/时间线就掉回蓝色 antd 壳——如果"规格单"是世界观，为什么交互系统都是从别处借来的皮肤？
2. 以"精确、受控、可追溯"为口号，为什么对自己最该精确追踪的阅读位置失忆？"CONTINUE READING" 这行字每次都在撒谎。
3. HTML 沙箱是登录页写的技术王牌，为什么它发生时的视觉全场最裸？最强的差异化能力在视觉上被藏了起来。
4. 分享页是产品对陌生人的唯一自我介绍，却主动摘掉了品牌——产品最想被记住的时刻反而最不像它自己。
